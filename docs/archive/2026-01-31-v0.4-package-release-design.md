# genui v0.4 包发布版本 - 设计文档

**设计日期:** 2026-01-31
**目标版本:** 0.4.0
**设计状态:** 已确认

## 执行摘要

v0.4 版本的核心目标是将 genui 打造成一个可发布的基本版本, 支持用户通过 wheel 文件手动安装并集成到自己的项目中. 主要改进包括: CLI 工具、增强的 Tools API、Headless 测试框架、完善的文档和规范化的打包流程.

## 设计原则

1. **保持向后兼容**: v0.3 的所有功能必须正常工作
2. **API 简洁性**: 暴露的 API 应该简单易懂, 复杂性封装在内部
3. **文档优先**: 通过文档而非代码复杂度来提升扩展性
4. **渐进增强**: 新功能作为可选特性, 不影响基础使用
5. **测试优先**: 新增功能必须有自动化测试覆盖

### 4. Tools 可定制化 (P0)

**需求:**
- 支持用户自定义 tools
- 提供两种注册方式: 基础 API 和装饰器

**实现:**

**方式 A - 基础注册 API:**
```python
from genui import ToolRegistry

registry = ToolRegistry()

def my_function(param: str) -> str:
    """函数描述"""
    return f"结果: {param}"

registry.register_tool(my_function)
```

**方式 B - 装饰器风格:**
```python
from genui import ToolRegistry, register_tool

registry = ToolRegistry()

@register_tool(registry)
def my_function(param: str) -> str:
    """函数描述"""
    return f"结果: {param}"
```

**技术实现:**
- 在 `genui/tools/__init__.py` 中导出 `register_tool`
- 实现 `register_tool(registry)` 装饰器工厂函数
- 装饰器内部调用 `registry.register_tool(func)`

**验收标准:**
- ✅ 两种方式都能正常注册工具
- ✅ 注册的工具可以在 UI 生成中被识别和调用
- ✅ 提供完整的自定义工具文档和示例

### 6. 自动化测试 (P0)

**需求:**
- 不依赖手动点击的自动化测试
- 覆盖核心功能和典型使用场景

**方案: Headless 测试**

**TestAdapter 设计:**
```python
class TestAdapter(AdapterBase):
    """测试适配器, 支持在内存中模拟 UI 交互"""

    def __init__(self):
        self.widgets = {}     # 存储虚拟组件
        self.events = []      # 记录事件
        self.outputs = []     # 记录输出

    # 测试辅助方法
    def click(self, component_id: str)
    def set_input(self, component_id: str, value: str)
    def get_output(self, component_id: str) -> str
    def select(self, component_id: str, option: str)
```

**测试用例示例:**
```python
def test_calculator_e2e():
    # 生成 UI
    generator = UIGenerator()
    ui = generator.generate("创建计算器")

    # 使用 TestAdapter
    adapter = TestAdapter()
    renderer = Renderer(adapter=adapter)
    renderer.render(ui)

    # 模拟交互
    adapter.set_input("num1", "10")
    adapter.set_input("num2", "5")
    adapter.select("operator", "+")
    adapter.click("calc_btn")

    # 验证结果
    result = adapter.get_output("result_label")
    assert "15" in result
```

**测试分层:**
1. 单元测试: 组件、工具、注册表 (已有)
2. 集成测试: 生成逻辑、渲染逻辑 (新增)
3. 端到端测试: 完整用户流程 (新增)

**验收标准:**

## 风险和依赖

### 技术风险

1. **LLM 生成不稳定**
   - 风险: 测试中 LLM 可能生成不一致的 UI
   - 缓解: 使用固定的 system prompt, 或 mock LLM 响应

2. **TestAdapter 实现复杂度**
   - 风险: 模拟所有组件交互可能比预期复杂
   - 缓解: 先实现核心组件, 后续迭代增加

### 依赖关系

- 依赖 v0.3 的稳定性
- 依赖 LangChain API 稳定
- 依赖 uv 构建工具
