# v0.1
## 概述
当前的UI每次生成后都是静态不变了, 这样用久了会显得较为单调, 并且很多UI元素都是固定的, 并且绝对大多数情况下可能都用不到. 在如今大模型时代, 我们可以依靠大模型的理解能力
每次根据用户的需求动态生成不同的UI界面进行交互, 这样可以大大提升趣味性. 由于这个想法暂时想不到落地的产品形态, 因此只作为探索性项目.

## 最终效果
目前的这个demo最终效果为: 
运行之后可以在输入框或终端中输入, 输入描述后, 程序会根据描述生成一个UI界面, 然后用户可以和这个UI界面进行交互, 比如点击按钮, 输入文本等.


## 设计思路
### 生成逻辑层
改层级由大模型驱动, 根据用户输入、已有的功能(可能为一些api、或者函数等)、预设的UI组件抽象, 生成一个UI实例, 这个实例应该能够正常展示、正常交互.

### 展示层
展示层负责将生成的UI实例渲染出来.

### UI组件抽象层
UI组件抽象层负责将不同框架、平台的UI组件抽象成通用的高级组件, 这些高级组件隐藏了所有不同的细节, 方便大模型统一理解. 
初步可以只做python中比较简单的UI库的抽象, 比如PyQt, Tkinter等, 后续可以扩展到其他平台.
要预留好接口, 方便后续扩展.

## 技术方案
使用python实现主体代码, uv管理依赖
不同的UI库使用optional依赖管理, 按需安装

### 日志系统
使用colorlog库, 可以在终端中输出不同颜色的日志, 方便调试.
日志文件在工作目录的logs目录下生成, 文件名为isoformat的时间戳.

### 代码管理
使用git进行版本控制

# v0.3

现在能够根据用户的需求(输入)生成交互界面, 但尚未考虑具体有哪些功能, 在v0.3版本中, 应该将已有的Function call 或 MCP 提供给大模型, 让其生成一个既贴合用户需求又不会超出现有能力的UI. 其中这些Function Call或MCP本质上都是对现有功能访问接口的封装. 你可以自己定义一些能力供测试使用.

# v0.4
## 总体目标
做一个包的基本版发布, 最终实现: 
- 最主要的目的是可以将generator暴露给用户, 用户可以集成在自己的项目中, 生成UI界面
- adapters层具有良好的抽象, 不同平台细节对generator是透明的, 用户可以继承我们的接口即可实现其他平台的适配
- 用户可以自定义自己的tools接入
- 可以提供一个简易入口程序, 就是当前的这种形态: 让用户输入描述, 然后生成UI界面, 用户可以和这个UI界面进行交互
对上上述目标如果现有代码已经实现的很好了就不需要改动, 如果并没有那么完备则进行改动, 另外这个基本版先不要对外开放. 有关测试的问题, 因为现在测试都是生成UI然后交互, 但我基本上不会在电脑上没办法帮你点击, 因此你需要想一些自动化的、非交互式的测试.
