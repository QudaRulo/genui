# v0.3 Tools 集成设计方案

**日期**: 2026-01-29
**版本**: v0.3
**目标**: 将 Function Call 和 MCP 能力集成到 UI 生成系统中

## 一、设计目标

在 v0.1 和 v0.2 的基础上, 增加实际功能调用能力, 让生成的 UI 不仅能展示和交互, 还能调用真实的功能(Function Call 或 MCP).

核心需求:
- 支持在 UI 的事件处理函数中调用外部功能
- LLM 能够根据可用功能生成合适的 UI
- 混合方案: 既支持简单函数定义, 也预留 MCP 集成接口
- 使用成熟框架(LangChain)减少维护成本

## 二、整体架构

v0.3 在现有基础上增加 **Tools 层** 和 **运行时支持层**, 整体分为 5 层:

```
┌─────────────────────────────────────┐
│     Tools 层 (新增)                  │
│  - ToolRegistry: 管理可用 tools      │
│  - 内置示例 tools                    │
│  - 支持用户自定义注册                │
└─────────────────────────────────────┘
           ↓
┌─────────────────────────────────────┐
│    生成逻辑层 (增强)                 │
│  - 阶段1: Tool 规划                  │
│  - 阶段2: UI 生成                    │
│  - 基于 LangChain                   │
└─────────────────────────────────────┘
           ↓
┌─────────────────────────────────────┐
│    运行时支持层 (新增)                │
│  - ToolExecutor: 执行 tools          │
│  - call_function(): 统一调用接口     │
└─────────────────────────────────────┘
           ↓
┌─────────────────────────────────────┐
│    UI 抽象层 (不变)                  │
│    渲染层 (增强)                     │
└─────────────────────────────────────┘
```

## 三、技术选型

### 框架迁移

- **从直接使用 OpenAI/Anthropic SDK 迁移到 LangChain**
  - 统一的抽象层, 减少维护成本
  - 完善的 tool calling 支持
  - 便于后续集成 MCP

### 依赖管理

```toml
[project.dependencies]
langchain-core = ">=0.1.0"        # 核心抽象
langchain-openai = ">=0.1.0"      # 默认支持 OpenAI 兼容 API

[project.optional-dependencies]
anthropic = ["langchain-anthropic>=0.1.0"]  # 可选 Anthropic 支持
```

- 默认支持 OpenAI 兼容 API (开箱即用)
- Anthropic 作为可选依赖: `uv sync --extra anthropic`
- 不安装完整的 `langchain` 包, 只装需要的子包

### Tool 调用方式

- **统一的同步接口**: `call_function(name, **kwargs)`
- 内部使用 `asyncio.run()` 处理异步 tools
- 保持与现有 `get_value()`/`set_value()` 的一致性
- 为未来真正的异步调用预留接口

#### ToolRegistry 类

```python
class ToolRegistry:
    """管理可用的 tools"""

    def __init__(self, load_builtin: bool = True):
        """初始化 tool 注册表

        Args:
            load_builtin: 是否自动加载内置 tools
        """
        self._tools: Dict[str, BaseTool] = {}
        if load_builtin:
            self._load_builtin_tools()

    def register(self, tool: BaseTool) -> None:
        """注册一个 tool

        Args:
            tool: LangChain BaseTool 实例
        """

    def get_tool(self, name: str) -> Optional[BaseTool]:
        """根据名称获取 tool

        Args:
            name: tool 名称

        Returns:
            Tool 实例, 如果不存在则返回 None
        """

    def get_all_tools(self) -> List[BaseTool]:
        """获取所有注册的 tools

        Returns:
            Tools 列表
        """

    def get_tools_description(self, tool_names: Optional[List[str]] = None) -> str:
        """生成 tools 的描述文本, 用于 LLM prompt

        Args:
            tool_names: 需要描述的 tool 名称列表, 如果为 None 则描述所有 tools

        Returns:
            格式化的 tools 描述字符串
        """
```

```python
class ToolExecutor:

    def __init__(self, registry: ToolRegistry):

            name: Tool 名称
            **kwargs: Tool 参数

        Returns:
            Tool 执行结果

        Raises:
            ValueError: Tool 不存在或参数错误
            RuntimeError: Tool 执行失败
        """
        # 1. 查找 tool
        # 2. 验证参数
        # 3. 执行 tool (内部处理异步)
        # 4. 错误处理
```

#### UI 生成 Prompt 增强

在现有 `SYSTEM_PROMPT` 基础上增加:

```python
# 在 "你可以使用以下UI组件" 之前插入:

你可以调用以下功能函数:

{selected_tools_description}

在事件处理函数中, 可以使用 call_function(name, **kwargs) 来调用这些功能:

示例:
```python
def handle_weather_query():
    # 获取用户输入
    city = get_value("city_input")

    # 调用功能函数
    weather_data = call_function("get_weather", city=city)

    # 更新 UI 显示
    result_text = f"{city}的天气: {weather_data['weather']}, 温度: {weather_data['temperature']}°C"
    set_value("result_label", result_text)
    display(f"查询成功: {result_text}")
```

call_function() 说明:
- 参数: name (函数名), **kwargs (函数参数)
- 返回: 函数执行结果
- 异常: 如果函数不存在或执行失败, 会抛出异常, 可以用 try/except 捕获
```

### 4.4 运行时支持层

#### Renderer 增强

```python
class Renderer:
    """渲染器, 增强事件处理函数执行环境"""

    def __init__(
        self,
        adapter: Optional[AdapterBase] = None,
        tool_executor: Optional[ToolExecutor] = None
    ):
        """初始化渲染器

        Args:
            adapter: UI 适配器
            tool_executor: Tool 执行器, 如果为 None 则创建默认实例
        """
        self.adapter = adapter or self._get_default_adapter()
        self.tool_executor = tool_executor or ToolExecutor(ToolRegistry())

    def _prepare_event_handler_globals(self) -> dict:
        """准备事件处理函数的全局环境

        Returns:
            包含所有可用工具函数的字典
        """
        return {
            # 现有的工具函数
            'get_widget': self._get_widget,
            'get_value': self._get_value,
            'set_value': self._set_value,
            'update_widget': self._update_widget,
            'display': self._display,
            'print': print,

            # 新增: tool 调用能力
            'call_function': self.tool_executor.call_function,
        }
```

#### 执行流程

```
用户操作 (如点击按钮)
    ↓
Adapter 触发事件处理函数
    ↓
事件处理函数执行:
  - get_value("input_id")       # 获取 UI 输入
  - call_function("tool_name")  # 调用功能
  - set_value("label_id")       # 更新 UI
    ↓
ToolExecutor.call_function():
  - 查找 tool
  - 验证参数
  - 执行 (同步包装异步)
  - 返回结果或抛出异常
    ↓
UI 更新完成
```

#### 错误处理

在 `ToolExecutor.call_function()` 中统一处理:

1. **Tool 不存在**:
   ```python
   raise ValueError(f"Tool '{name}' 不存在")
   ```

2. **参数错误**:
   ```python
   raise ValueError(f"Tool '{name}' 参数错误: {error_details}")
   ```

3. **执行异常**:
   ```python
   raise RuntimeError(f"Tool '{name}' 执行失败: {error_message}")
   ```

事件处理函数可以捕获这些异常并在 UI 中显示友好提示.

## 五、LangChain 迁移

### LLMClient 重构

```python
class LLMClient:
    """LLM客户端, 基于 LangChain 实现"""

    def __init__(
        self,
        model: Optional[str] = None,
        provider: Optional[Literal["openai", "anthropic"]] = None,
        **kwargs
    ):
        """初始化客户端

        Args:
            model: 模型名称
            provider: 提供商, 默认从环境变量读取或使用 openai
            **kwargs: 传递给 LangChain ChatModel 的其他参数
        """
        self.provider = provider or os.getenv("LLM_PROVIDER", "openai")

        if self.provider == "openai":
            from langchain_openai import ChatOpenAI
            self.llm = ChatOpenAI(
                model=model or os.getenv("OPENAI_MODEL", "gpt-4o"),
                api_key=os.getenv("OPENAI_API_KEY"),
                base_url=os.getenv("OPENAI_BASE_URL"),
                **kwargs
            )
        elif self.provider == "anthropic":
            from langchain_anthropic import ChatAnthropic
            self.llm = ChatAnthropic(
                model=model or os.getenv("ANTHROPIC_MODEL", "claude-3-5-sonnet-20241022"),
                api_key=os.getenv("ANTHROPIC_API_KEY"),
                **kwargs
            )
        else:
            raise ValueError(f"不支持的 provider: {self.provider}")

    def generate_ui_config_sync(
        self,
        user_description: str,
        system_prompt: str
    ) -> str:
        """同步调用 LLM 生成配置

        Args:
            user_description: 用户描述
            system_prompt: 系统提示词

        Returns:
            LLM 返回的文本
        """
        from langchain_core.messages import SystemMessage, HumanMessage

        messages = [
            SystemMessage(content=system_prompt),
            HumanMessage(content=user_description)
        ]

        response = self.llm.invoke(messages)
        return response.content
```

## 六、向后兼容性

### 默认行为

1. **UIGenerator**:
   - 如果不传 `tool_registry`, 自动创建默认实例 (包含内置 tools)
   - 用户可以传入空 registry 禁用 tools:
     ```python
     UIGenerator(tool_registry=ToolRegistry(load_builtin=False))
     ```

2. **Renderer**:
   - 如果不传 `tool_executor`, 自动创建默认实例
   - 即使 UI 中没有 `call_function()` 调用, 也能正常渲染

3. **示例代码**:
   - 现有的 `examples/demo.py` 无需修改即可运行
   - 新增 `examples/demo_with_tools.py` 展示 tools 功能

### 可选性

- Tools 功能是增量的, 不破坏现有功能
- v0.1/v0.2 生成的 UI 在 v0.3 中仍然可以正常运行
- 只有在事件处理函数中显式调用 `call_function()` 时才会使用 tools

## 十一、风险和挑战

1. **LangChain 版本兼容性**
   - 风险: LangChain 更新频繁, API 可能变化
   - 缓解: 锁定小版本范围, 定期测试

2. **两阶段生成延迟**
   - 风险: 两次 LLM 调用增加等待时间
   - 缓解: 第一阶段使用更快的模型, 缓存 tool 规划结果

3. **Tool 安全性**
   - 风险: 用户自定义 tools 可能有安全隐患
   - 缓解: 提供安全指南, 考虑沙箱执行环境

4. **错误传播**
   - 风险: Tool 执行失败可能导致 UI 无响应
   - 缓解: 完善的错误处理和用户提示

## 十二、总结

v0.3 设计方案通过引入 LangChain 和两阶段生成机制, 实现了 UI 生成与功能调用的深度集成. 关键特性:

- ✅ 基于 LangChain, 减少维护成本
- ✅ 两阶段生成, 提高 tool 选择精度
- ✅ 统一的同步调用接口, 易于使用
- ✅ 完善的向后兼容性
- ✅ 预留 MCP 集成接口
- ✅ 6 个内置示例 tools, 覆盖多种场景

该方案平衡了功能完整性、实现复杂度和未来扩展性, 适合作为探索性 demo 的下一阶段演进.
